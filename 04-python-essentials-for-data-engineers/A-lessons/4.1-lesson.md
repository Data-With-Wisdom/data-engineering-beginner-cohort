# Lesson 4.1: Introduction to Python for Data Engineering

## What is Python?

**Python** is a high-level, general-purpose programming language created by Guido van Rossum in 1991.

**Simple definition:** A programming language designed to be easy to read and write.

**What makes Python special:**
- 📖 **Readable syntax** - Looks almost like plain English
- 🚀 **Beginner-friendly** - Easiest language to learn
- 🔧 **Versatile** - Used for web apps, data science, automation, AI, and more
- 📚 **Huge ecosystem** - Thousands of free libraries (pre-built tools)
- 🌍 **Popular** - One of the most widely used languages in the world

---

## Why Python for Data Engineering?

Data Engineers use Python for **data processing, automation, and building pipelines**.

**Here's what you'll do with Python as a Data Engineer:**

✅ **Extract data** - Pull data from APIs, databases, files  
✅ **Transform data** - Clean messy data, reshape formats, calculate new fields  
✅ **Automate pipelines** - Write scripts that run automatically  
✅ **Process files** - Read/write CSV, JSON, Excel, Parquet files  
✅ **Call APIs** - Fetch data from external services  
✅ **Orchestrate workflows** - Control when and how data moves  
✅ **Data quality checks** - Validate data is correct

## Python vs Other Languages

**Why Python instead of Java, C++, or JavaScript?**

| Language | Pros | Cons | Used For |
|----------|------|------|----------|
| **Python** | Easy to learn, great for data, huge ecosystem | Slower than compiled languages | Data science, automation, scripting |
| **Java** | Fast, enterprise-standard | Verbose, harder to learn | Large enterprise systems, Android |
| **C++** | Very fast, low-level control | Complex, steep learning curve | System software, games, performance-critical apps |
| **JavaScript** | Runs in browsers, full-stack web | Not ideal for data processing | Web development (frontend + backend) |
| **R** | Built for statistics | Limited outside data analysis | Statistical analysis, research |

**For data engineering, Python is the clear winner:**
- ✅ Easy to learn and read
- ✅ Best data processing libraries (Pandas, NumPy)
- ✅ Works with all data tools (Spark, Airflow, dbt)
- ✅ Quick to prototype and iterate
- ✅ Massive community and resources

## What is the Python Interpreter?

**An interpreter is a program that reads and executes Python code line by line.**

**How it works:**
```
You write Python code → Python interpreter reads it → Computer executes it
```

**Think of the interpreter as a translator:**
- You speak Python (human-readable)
- Interpreter translates to machine language (0s and 1s)
- Computer understands and does what you asked

## Two Ways to Run Python Code

### **1. Interactive Mode (Python Shell / REPL)**

**REPL = Read-Eval-Print-Loop**

Open your terminal/command prompt and type:
```bash
python
```

or
```bash
python3
```

You'll see:
```
Python 3.11.0 (main, Oct 24 2022, 18:26:48)
>>> 
```

**The `>>>` is the Python prompt.** You can type code and press Enter to execute:
```python
>>> 2 + 2
4
>>> print("Hello World")
Hello World
>>> name = "Ahmed"
>>> print(f"My name is {name}")
My name is Ahmed
```

**Use interactive mode for:**
- ✅ Quick tests ("Does this work?")
- ✅ Experimenting with new functions
- ✅ Calculating things quickly
- ❌ Not for writing full programs

**To exit:** Type `exit()` or press Ctrl+D (Mac/Linux) / Ctrl+Z then Enter (Windows)

---

### **2. Script Mode (Writing .py Files)**

**For real programs, you write code in a file and run it.**

**Step 1:** Create a file called `hello.py`

**Step 2:** Write code in the file:
```python
# hello.py
print("Hello from a Python script!")
name = "Chioma"
print(f"Welcome, {name}!")
```

**Step 3:** Run the script from terminal:
```bash
python hello.py
```

or
```bash
python3 hello.py
```

**Output:**
```
Hello from a Python script!
Welcome, Chioma!
```

**Use script mode for:**
- ✅ Real programs (data processing scripts, pipelines)
- ✅ Code you want to save and reuse
- ✅ Automating tasks
- ✅ Anything longer than 5 lines

## Virtual Environments: Why They Matter

### **The Problem Virtual Environments Solve**

Imagine this scenario:

**Project A needs:**
- pandas version 1.5
- requests version 2.28

**Project B needs:**
- pandas version 2.0
- requests version 2.25

**If you install both globally on your computer, they conflict!**

**Project B's installation overwrites Project A's dependencies, and Project A breaks.**

---

### **What is a Virtual Environment?**

A **virtual environment** is an isolated Python environment for each project.

**Think of it as:**
- A separate "bubble" for each project
- Each bubble has its own Python packages
- Changes in one bubble don't affect others
```
Your Computer
├── Project A (virtual env)
│   ├── Python 3.11
│   ├── pandas 1.5
│   └── requests 2.28
│
├── Project B (virtual env)
│   ├── Python 3.11
│   ├── pandas 2.0
│   └── requests 2.25
│
└── No conflicts! ✅
```

---

### **Creating a Virtual Environment**

**Step 1: Navigate to your project folder**
```bash
cd /path/to/your/project
# Example:
cd ~/data-engineering-course/week4
```

**Step 2: Create virtual environment**
```bash
python -m venv venv
```

**What this does:**
- `python -m venv` = Run Python's built-in venv module
- `venv` (second one) = Name of the folder to create (can be anything, but "venv" is convention)

**This creates a `venv/` folder in your project:**
```
week4/
├── venv/              ← Virtual environment folder
│   ├── bin/           ← Executables (Mac/Linux)
│   ├── Scripts/       ← Executables (Windows)
│   ├── lib/           ← Installed packages go here
│   └── ...
├── script.py          ← Your Python code
└── data.csv           ← Your data files
```

---

### **Activating the Virtual Environment**

**Before you can use it, you must activate it.**

**Mac/Linux:**
```bash
source venv/bin/activate
```

**Windows (Command Prompt):**
```cmd
venv\Scripts\activate
```

**Windows (PowerShell):**
```powershell
venv\Scripts\Activate.ps1
```

**If PowerShell gives permission error:**
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Then try activating again.

---

**When activated, your prompt changes:**
```
(venv) your-computer:week4 username$
```

**The `(venv)` prefix means the virtual environment is active.**

---

### **Installing Packages in Virtual Environment**

**With the venv activated, any packages you install stay in that environment only.**
```bash
(venv) $ pip install pandas
```

**This installs pandas ONLY for this project, not globally.**

---

### **Deactivating the Virtual Environment**

**When you're done working:**
```bash
deactivate
```

**The `(venv)` prefix disappears:**
```
your-computer:week4 username$
```

You're back to your system's global Python.

---

### **Virtual Environment Best Practices**

✅ **Create a new venv for each project**  
✅ **Always activate before working** (`source venv/bin/activate`)  
✅ **Add `venv/` to `.gitignore`** (don't commit it to Git)  
✅ **Document dependencies** (we'll cover `requirements.txt` later)  
❌ **Don't edit files inside `venv/` folder** (it's auto-generated)

## Your First Python Program

Let's write a simple data-related Python script.

**Create a file: `hello_data.py`**
```python
# hello_data.py

# This is a comment - Python ignores this line
# Comments explain what code does

# Print a message
print("Hello, Data Engineering!")

# Variables store data
name = "Ahmed"
role = "Data Engineer"
years_experience = 2

# Print with variables
print(f"My name is {name}")
print(f"I am a {role}")
print(f"I have {years_experience} years of experience")

# Do some calculations
hours_per_week = 40
weeks_per_year = 52
total_hours = hours_per_week * weeks_per_year

print(f"I work {total_hours} hours per year")

# Work with a list (like an Excel column)
cities = ["Lagos", "Abuja", "Port Harcourt"]
print(f"I've worked in {len(cities)} cities:")
for city in cities:
    print(f"  - {city}")
```

**Run it:**
```bash
python hello_data.py
```

**Output:**
```
Hello, Data Engineering!
My name is Ahmed
I am a Data Engineer
I have 2 years of experience
I work 2080 hours per year
I've worked in 3 cities:
  - Lagos
  - Abuja
  - Port Harcourt
```

## Python Syntax Rules

**Unlike SQL or other languages, Python cares about spacing and indentation.**

### **1. Indentation Matters**

**❌ Wrong:**
```python
for city in cities:
print(city)  # Error: Not indented
```

**✅ Correct:**
```python
for city in cities:
    print(city)  # Indented 4 spaces
```

**Python uses indentation to show which code belongs together (blocks).**

Standard: **4 spaces** per indentation level.

---

### **2. Case Sensitivity**
```python
name = "Ahmed"
print(name)  # Works
print(Name)  # Error: Name is not defined (capital N)
```

`name` and `Name` are different variables.

---

### **3. No Semicolons Needed**

**Other languages:**
```java
int x = 5;  // Semicolon required
```

**Python:**
```python
x = 5  # No semicolon needed
```

Each line is a statement. Semicolons optional (usually omitted).
