# Lesson 6.2: Repository Structure and READMEs

## Why this matters
A project is easier to understand when its files are organized clearly. A well-structured repository helps a teammate or future version of yourself know what to do next.

## A simple repository structure
A beginner-friendly project might look like this:
```text
my-project/
├── data/
├── scripts/
├── README.md
├── requirements.txt
└── outputs/
```

## What belongs in a README
A good README usually explains:
- what the project does
- the tools or languages used
- how to install dependencies
- how to run the project
- where the main files are

## Good repository habits
- use clear folder names
- keep scripts and data separate
- name files in a predictable way
- document assumptions and setup steps

## Example
If a project contains a cleaning script, a dataset, and some output files, the README should tell the learner exactly how those pieces connect.

## Key takeaway
A repository is not only code. It is also communication. A strong README makes your work accessible to others.
